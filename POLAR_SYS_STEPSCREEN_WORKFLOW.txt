================================================================================
  polar-sys — iframe embed + waypoint sidebar
================================================================================

DEPLOYED APP
  Steps load from:
    https://polar-sys.vercel.app/#/anomaly (and #/monitor, #/incident)

  Embed base is centralized in `src/polarSysUrl.ts` with default above. Sidebar
  step ids (`anomaly`, `incident`, `monitor`) map to those hashes via
  `POLAR_SYS_HASH` in `src/store/flowStore.ts` and iframe `src` from
  `polarSysIframeHref()`.

  Clicking the sidebar calls `goToStepById` → parent `window.location.hash` and
  the iframe `polarHash` align so polar-sys opens the matching route.

OVERRIDE
  Env: `VITE_POLAR_SYS_ORIGIN=https://your-host.example.com` (no trailing slash).

SHELL ↔ POLAR (inside iframe)
  If polar-sys posts `postMessage(window.parent, { type: 'polar-hash',
  hash: '#/incident' }, 'https://polar-sys.vercel.app')`, the waypoint sidebar
  updates to stay in sync with in-app navigations.

EMBEDDING (CSP)
  polar-sys must allow this shell’s origin in `Content-Security-Policy`
  `frame-ancestors` (or equivalent), or the iframe stays blank.
